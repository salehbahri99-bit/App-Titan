# Titan Print — قسم التصميم / الطلبات

صفحة واجهة لقسم **تصميم** تعرض قائمة الطلبات مع الفلاتر، بنفس ستايل التطبيق (RTL، خلفية كريمية، لون أساسي برتقالي `#e8873a`).

## المضاف في هذا التحديث

**بطاقة الطلب + زر نسخ البيانات**

بالضغط على أي طلب في القائمة تُفتح بطاقة الطلب (نفس شكل شاشة الطلب في التطبيق: شريط علوي داكن مع رقم الطلب والحالة، صف الإجراءات، ثم لوحة «بيانات الطلب»).

أول زر في صف الإجراءات هو **نسخ البيانات** — بالضغط عليه يُنسخ للحافظة:

```
الاسم: ايمن الفحماوي
الجوال: 0544631008
العنوان: الطيرة ـ المثلث
المبلغ: 450 ₪
التوصيل: 65 ₪
```

يتحوّل الزر إلى «تم النسخ ✓» لثانيتين وتظهر رسالة تأكيد أسفل الشاشة. النسخ يستخدم `navigator.clipboard` وعند عدم توفّره (اتصال `http` أو متصفح قديم) يرجع تلقائياً لطريقة `textarea` + `execCommand`، وإن فشل الاثنان تظهر رسالة «تعذّر النسخ».

صيغة النص المنسوخ في دالة `orderText()` داخل `index.html` — عدّل الترتيب أو الحقول من هناك.

---

فلتر **الترتيب** فوق صف «الطلبات النشطة / الطلبات المنفذة» مباشرة:

- **الأحدث** — يرتّب الطلبات تنازلياً حسب تاريخ الإنشاء (الافتراضي).
- **الأقدم** — يرتّب الطلبات تصاعدياً.

الزر النشط بلون برتقالي `#e8873a` بنفس شكل بقية الفلاتر (Segmented pills)، مع أيقونة سهم لأسفل/لأعلى توضّح اتجاه الترتيب.

## لوحة التحكم — `dashboard.html`

نموذج تفاعلي للوحة التحكم بنفس ستايل التطبيق، تُفتح من زر **لوحة** في شريط التنقل. بلا خادم
وبلا مكتبات — ملف واحد.

**ما تعرضه:**

- **فلتر الفترة:** 7 أيام / 30 يوماً / 90 يوماً — يحدّث المؤشرات والرسم والتوزيع وأفضل الزبائن.
- **خمسة مؤشرات:** المبيعات، عدد الطلبات، متوسط قيمة الطلب (كل منها مع نسبة التغيّر عن الفترة
  السابقة)، الطلبات قيد التنفيذ، والطلبات المتأخرة. الضغط على «متأخرة» يعرض الطلبات المتأخرة فقط.
- **رسم المبيعات:** أعمدة يومية (أسبوعية في فترة 90 يوماً) مع تلميح عند المرور: المبلغ والتاريخ
  وعدد الطلبات.
- **توزيع الطلبات** حسب النوع + **شريط التحصيل** (المحصّل مقابل المتبقي على الزبائن).
- **مراحل الإنتاج:** تصميم ← بانتظار الموافقة ← طباعة ← تشطيب وتغليف ← جاهز للتسليم، مع عدد
  المتأخر في كل مرحلة. الضغط على مرحلة يفلتر جدول الطلبات.
- **جدول الطلبات الجارية** مرتّب حسب الأقرب تسليماً / الأحدث / الأعلى قيمة. الضغط على طلب يفتح
  بطاقته: البيانات، شريط التقدّم، زر **نقل للمرحلة التالية**، نسخ البيانات، وواتساب.
- **متابعات اليوم:** طلبات جاهزة للتسليم + زبائن تجاوزوا دورة الشراء المعتادة، مع زر واتساب.
- **أفضل الزبائن** في الفترة المختارة.
- **طلب جديد** (زر أو اختصار `N`): يُضاف مباشرة لمرحلة «تصميم» ويظهر في الجدول.

**البيانات:** دالة `buildSeed()` تولّد بيانات تجريبية ثابتة نسبةً لتاريخ اليوم — استبدلها بمصدر
الطلبات الحقيقي. حقول الطلب: `id`, `customer`, `phone`, `address`, `type`
(`clothes`/`packaging`/`print`/`signage`), `stage` (`design`/`approval`/`print`/`finish`/`ready`/`delivered`),
`total`, `paid`, `createdAt`, `due`. التعديلات (نقل المراحل، الطلبات الجديدة) تُحفظ في `localStorage`
(مفتاح `titan_dashboard_v1`) وتُعاد البيانات التجريبية كل يوم.

## شاشة الزبائن (CRM) — `customers.html`

شاشة إدارة زبائن كاملة بنفس ستايل التطبيق، تُفتح من زر **الزبائن** في شريط التنقل (أو مباشرة
`customers.html`). تعمل بلا خادم — كل الحسابات تجري في المتصفح.

**ما تعرضه:**

- **شريط مؤشرات:** إجمالي الزبائن، النشطون (آخر 90 يوماً)، زبائن VIP، من يحتاجون متابعة.
- **بحث فوري** بالاسم أو النشاط أو المدينة أو الجوال، مع تطبيع عربي (يجد «الأفق» بكتابة
  «الافق») وتطبيع أرقام الهاتف. اختصار `Ctrl + K`.
- **تنبؤ بدورة الشراء:** متوسط الفاصل بين الطلبات + الانحراف المعياري ← تاريخ الطلب القادم
  المتوقع، وتمييز المتأخرين بلون أحمر.
- **تصنيف RFM** تلقائي: `VIP` / `منتظم` / `متقطع` / `جديد`.
- **فلاتر:** التصنيف، الحالة (كل الزبائن / يحتاج متابعة / متأخر)، والترتيب (الأقرب استحقاقاً /
  الأحدث طلباً / الأكثر إنفاقاً).
- **إجراءات سريعة** على كل صف: رسالة واتساب بقالب جاهز، فتح الملف، ملاحظة، تذكير.
- **ملف الزبون:** بيانات + تبويبات (نظرة عامة / الطلبات / الملاحظات / النشاط والتذكيرات)، وزر
  **نسخ البيانات** بنفس سلوك بطاقة الطلب.
- **تصدير** الجدول المفلتر إلى ملف CSV بترميز UTF-8 يفتحه Excel مباشرة.

**واتساب:** الرسائل تُفتح عبر روابط `wa.me` بنقرة يدوية (لا يوجد WhatsApp Business API)، ويُسجَّل
كل إرسال في سجل التواصل.

**البيانات:** مصفوفة `SEED` داخل `customers.html` بيانات تجريبية — استبدلها بمصدرك. الملاحظات
والتذكيرات وسجل التواصل تُحفظ في `localStorage` للمتصفح (مفتاح `titan_crm_v1`)، وتُستبدل
بمسارات الـ API عند ربط الخادم.

## الطبقة الخلفية — `crm-server/`

تنفيذ كامل لوثيقة `docs/TITAN_CRM_IMPLEMENTATION.md` بـ Next.js + Prisma + Medusa: ستة جداول CRM،
مسارات API، مهمة ليلية لإعادة حساب الدورات و RFM مع إشعار n8n للمتأخرين، ومكوّنات React.

هذا المستودع صفحات ساكنة بلا Next.js، لذلك بُني المجلد **تطبيقاً مستقلاً قابلاً للتثبيت** جاهزاً
للنقل إلى مستودع Titan Print الفعلي — لا يؤثر على الموقع الساكن ولا على نشر Pages. التفاصيل
وخطوات التشغيل والنقاط التي تحتاج قراراً منك في `crm-server/README.md`.

المعادلات في `customers.html` مطابقة لتلك في `crm-server/lib/crm/` حتى تبقى النتائج واحدة بعد
الربط.

## التشغيل

الملفات مستقلة بالكامل — لا تحتاج أي مكتبات أو خطوات بناء:

```
افتح index.html في المتصفح      # قسم التصميم / الطلبات
افتح customers.html في المتصفح  # شاشة الزبائن (CRM)
افتح dashboard.html في المتصفح  # لوحة التحكم
```

## النشر (GitHub Pages)

يوجد workflow جاهز في `.github/workflows/deploy-pages.yml` ينشر الموقع تلقائياً مع كل push على الفرع الافتراضي.

رابط الموقع بعد النشر:

```
https://salehbahri99-bit.github.io/App-Titan/
```

**خطوة مطلوبة مرة واحدة** من إعدادات المستودع (لا يمكن أتمتتها — التوكن الافتراضي لـ Actions لا يملك صلاحية إنشاء موقع Pages):

`Settings` ← `Pages` ← `Build and deployment` ← `Source` = **GitHub Actions**

ثم شغّل الـ workflow من تبويب `Actions` (زر *Run workflow*) أو ادفع أي تعديل جديد.

## الربط بالبيانات الحقيقية

في `index.html` استبدل مصفوفة `ORDERS` بمصدر البيانات عندك. كل طلب يحتاج الحقول:

| الحقل | الوصف |
|---|---|
| `id` | رقم الطلب |
| `customer` | اسم الزبون |
| `type` | `clothes` أو `other` |
| `status` | `active` أو `done` |
| `createdAt` | تاريخ الإنشاء (`YYYY-MM-DD`) |
| `phone` | رقم الجوال (يُنسخ) |
| `address` | العنوان / البلدة (يُنسخ) |
| `total` | المبلغ (يُنسخ) |
| `delivery` | سعر التوصيل (يُنسخ) |
| `pieces` | إجمالي القطع |

رمز العملة في الثابت `CURRENCY` (الافتراضي `₪`).

منطق الترتيب موجود في دالة `render()`:

```js
.sort((a, b) => state.sort === "newest"
  ? new Date(b.createdAt) - new Date(a.createdAt)   // الأحدث أولاً
  : new Date(a.createdAt) - new Date(b.createdAt)); // الأقدم أولاً
```

الفلاتر الثلاثة (النوع، الترتيب، الحالة) تشتغل مع بعض، والأعداد في الشارات ثابتة في الـ HTML — اربطها بعدد النتائج الفعلي عند التوصيل بالبيانات.
